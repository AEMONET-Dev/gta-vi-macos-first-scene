# 两支原始计算着色器的开源翻译实测

> Historical lab entry. Measurements and corrections are dated below. Unlinked filenames identify local inputs or outputs from that run.

在 Apple M5 Max 上把归档的原始 DXIL 用 dxil-spirv 转成 SPIR-V，经过 spirv-val 校验，用 SPIRV-Cross 转成 MSL 3.2，再由系统 Metal 库编译并执行。输入使用游戏归档的全部资源、采样器和 dispatch 组数。项目正式渲染路径没有变化。

| 归档输入 | GPU 工作组 | 完全一致的输出 | 默认绑定下有差异的字节 |
| --- | --- | --- | --- |
| c7 第一次 | 1,020 × 1 × 1 | 9/10 | 1,048 |
| c7 第二次 | 1,020 × 1 × 1 | 9/10 | 849 |
| 8bb 非空样本 | 296 × 1 × 1 | 5/10 | 132,538 |

每行共验证 3,438,080 个字节。c7 的两份差异都集中在 Uav-s1-d120。8bb 有五张输出不同，不能仅归因于原来发现的两张存在写入竞争的纹理。更换两种额外的纹理视图映射后，三份样本通过张数都没有改变。逐输出 SHA-256、原游戏写入字节数和比较结果见 results.json。本次变体均未通过全部输出，单次调度日志的 GPU 时间不能证明等价提速。存在并发写的着色器可能会在重跑时产生不同的差异字节数。

## 复现

从本目录运行 `python3 verify.py` 可以验算已保存的九组输出。`python3 verify.py --rerun --output rerun.json` 会重新编译本目录的 Metal 宿主，重跑九组并更新这些输出。需要本机归档仍在原有位置。

要从两个原始 DXIL 开始，使用下列固定版本的命令，然后设置 OPEN_SHADER_BUILD 为构建目录的绝对路径并执行本目录的 reproduce.sh。可在 conversion.log 中查看翻译器命令、验证器退出码及重建的逐字节一致性。gpu.log 保留了六组库及 Metal 计算管线创建的早期检查。真实回放使用名称含 bindless.native 的两个 MSL 文件，两者均已在 Metal 上执行。

```sh
git clone https://github.com/HansKristian-Work/dxil-spirv.git
git -C dxil-spirv checkout 694cc674380a47767b56d63b9dec196aec963115
git -C dxil-spirv submodule update --init --recursive
cmake -S dxil-spirv -B build -G Ninja -DCMAKE_BUILD_TYPE=Release -DCMAKE_CXX_FLAGS_RELEASE='-O1 -DNDEBUG'
cmake --build build --target dxil-spirv spirv-cross spirv-val
```

宿主按 MSL 输出提供 Metal Tier 2 参数缓冲区，把资源 ID、采样器和根常量表分别绑定到 0、2 和 5 号缓冲区，并在 6 号缓冲区传入指向首个条目的偏移。线性缓冲区通过原生纹理视图读取。以上是可回放的实验性资源映射，其浮点、采样和资源读取语义还需逐项核实。
